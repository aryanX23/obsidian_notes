# Installation and Hello World

> [!info] Source
> 🎬 [Golang installation and hello world](https://www.youtube.com/watch?v=62qGe9yhiJI) · Section **01 Introduction** of [[Golang Notes]]
> ⬅️ [[Welcome to Go]] · ➡️ [[GOPATH and Go Docs]]

## Overview

This is the first hands-on video: install the Go toolchain, set up VS Code, create the project structure the whole series uses, and run a `Hello World`. Along the way you meet three things you will repeat in every later note: `go mod init`, the `package main` / `func main()` entry point, and `go run`. The explanation of the generated `go.mod` file is deferred to [[Go Modules]]; cross-platform builds are covered in [[Building for Windows, Linux and Mac]].

## The official home: go.dev

Everything official lives in one place. At the time of recording the site was `golang.org`; it now redirects to **go.dev**.

| What | Where |
|---|---|
| Downloads for every OS | https://go.dev/dl/ |
| Documentation, tutorials, language spec | https://go.dev/doc/ and https://go.dev/ref/spec |
| Package documentation (standard library and third party) | https://pkg.go.dev/ |
| Online Playground | https://go.dev/play/ |

> [!warning] Install the latest version
> The series was recorded on **Go 1.17**. Anything newer is fine and recommended, and the companion code works unchanged. Older versions are not recommended: early releases had a weaker garbage collector that was later rewritten, and dependency handling moved from `GOPATH` to **modules**, which is the "modern" way this series uses throughout.

### Why not just use the Playground?

The Playground runs your code on a remote, sandboxed server. It is fine to test a small algorithm, but it is a poor place to *learn* Go for real work:

- You cannot see or configure the environment it runs in.
- Packages that depend on the machine, such as `time` and random numbers, behave unexpectedly there (the instructor returns to this in [[Switch Case]]).
- Real applications need a local toolchain, a file structure, and modules.

## Installing Go

1. Open https://go.dev/dl/ and download the installer for your OS (about 65 MB).
   - **Windows**: the `.msi` installer, click through "I agree / Next".
   - **macOS**: the `.pkg` installer; it installs to `/usr/local/go` and puts `/usr/local/go/bin` on your `PATH`. If an older Go is detected it is removed first.
   - **Linux**: extract the tarball to `/usr/local` and add `/usr/local/go/bin` to your `PATH`:
     ```bash
     sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.xx.linux-amd64.tar.gz
     export PATH=$PATH:/usr/local/go/bin   # add this to ~/.bashrc or ~/.zshrc
     ```
2. Verify in a fresh terminal:
   ```bash
   go version
   ```
   **Output:**
   ```text
   go version go1.27.3 darwin/arm64
   ```
   (your version and platform will differ)

## The code editor: VS Code plus the Go extension

Use a real **code editor**, not a word processor. The series uses Visual Studio Code; Sublime Text or anything similar works too.

1. In VS Code, open Extensions and search for **Go**. Install the one published by the **Go Team at Google** (extension id `golang.go`), not any "preview" or third-party clone.
2. The first time you open a `.go` file the extension offers to install its helper tools (the `gopls` language server, the `dlv` debugger, linters). Click **Install All** every time it asks; these tools provide IntelliSense, auto-formatting and auto-imports.

## Project structure for the series

Create one root folder for the whole course and follow the instructor's naming **exactly** until [[Go Modules]] explains what the names mean.

```text
mygolang-lco/
└── 01hello/
    ├── go.mod        ← generated by `go mod init`
    └── main.go       ← your code
```

Open `mygolang-lco` in VS Code, create the folder `01hello`, and inside it the file `main.go`. Right-click the folder and choose **Open in Integrated Terminal** so that the terminal is already inside `01hello`.

## Step 1: `go mod init`

Before writing any code, initialise a **module** in the folder. Think of it (loosely) as `npm init` for Go:

```bash
go mod init hello
```

The official recommendation is to name the module after the repository that will host it, for example `go mod init github.com/<your-name>/hello`. The series keeps it short (`hello`) for now and switches to the full form later.

The command creates **`go.mod`**:

```text
module hello

go 1.27.3
```

It records the module name and the Go version used. You do not need `go mod tidy` or any other command yet. Everything about this file is explained in [[Go Modules]]; for now, just create it in every new folder.

## Step 2: the Hello World program

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello from LearnCodeonline.in")
}
```

What each line means:

| Line | Meaning |
|---|---|
| `package main` | Every Go file belongs to a package. `main` is special: it tells the compiler this is an **executable program**, not a library. |
| `import "fmt"` | Brings in the **fmt** (format) package from the standard library for printing. You rarely type this yourself: the Go extension adds and removes imports on save. |
| `func main()` | The **entry point**. Like C and C++, a Go program always starts at `main` inside package `main`. `main` is reserved; you cannot name anything else `main` at the package level. |
| `fmt.Println(...)` | Prints the text followed by a newline. Note the capital **P**: see below. |

> [!tip] Let the editor write the imports
> Type `fmt.Println(...)` and save. The extension (through `gopls`/`goimports`) adds `import "fmt"` automatically, and removes imports you stop using. This is why the instructor never writes import statements by hand. More on the lexer and formatting in [[Lexer and Types]].

> [!note] Case matters, predictably
> Go is case sensitive, and the case carries meaning: identifiers that start with a **capital letter are exported** (usable from other packages). `Println` is capitalised because the `fmt` package exports it. This rule is explained in [[Lexer and Types]] and reappears in [[Variables, Types and Constants]].

## Step 3: run it

```bash
go run main.go
```

**Output:**
```text
Hello from LearnCodeonline.in
```

`go run` compiles the program to a temporary location and runs it; it does **not** leave an executable behind. To produce a real binary (for this OS or another one) use `go build`, covered in [[Building for Windows, Linux and Mac]].

You can also run the whole package in the current directory with:

```bash
go run .
```

## Gotchas and Best Practices

> [!warning] `package main` and `func main()` are both required for an executable
> A file with `package hello` and a `main` function will not run as a program. The pair `package main` + `func main()` is the contract.

> [!warning] Unused imports are compile errors
> Go refuses to build if you import a package you never use. This is not a warning; it is an error. The editor's auto-import keeps you out of trouble, and you will meet the same strictness for unused variables in [[Variables, Types and Constants]].

> [!tip] Keep the terminal inside the folder you are working in
> Every `go` command (`go mod init`, `go run`, `go build`) acts on the current directory. Opening the integrated terminal from the right folder avoids a whole class of "cannot find package" confusion.

> [!tip] Terminal shortcut
> `Ctrl + L` clears the integrated terminal.

## Modern Go Notes

- `golang.org` is now `go.dev`; package docs are on `pkg.go.dev`.
- The `go.mod` written by current versions records the full patch version (for example `go 1.27.3`) where the video shows `go 1.17`.
- Installing command-line tools is done with `go install example.com/tool@latest`; `go get` no longer installs binaries. The VS Code extension handles this for its own tools when you click **Install All**.
